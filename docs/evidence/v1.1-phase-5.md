## Metric formulas (§2 verbatim)

| Tile | Formula implemented |
|---|---|
| **Orders completed** | `COUNT(*)` + `Σ Order.total` where `simpleStatus = COMPLETED` AND `completedAt ∈ IST month` |
| **Payment received** | `Σ Payment.amount` where `paidOn ∈ IST month` AND `status ≠ REJECTED` AND the order is not cancelled |
| **Pending orders** | `COUNT(*)` + `Σ balanceDue` where `simpleStatus = PENDING` (any date — these are what's still open) |
| **Achieved per employee** | `Σ Order.total` where `simpleStatus ≠ CANCELLED` AND `orderDate ∈ IST month` AND `salespersonId = X` |
| **Target per employee** | `SalesTarget[tenantId,userId,monthStart]` → fallback `TenantSettings.defaultMonthlyTarget` → 0 ("No target") |
| **% achieved** | `achievedPct(achieved, target)` from `src/server/domain/v1_1/achieved.ts` — rounded whole %, null when target is 0 |

## Live mechanism

- Server renders the initial 8 rows.
- `LatestOrdersLive` sets up a `setInterval(poll, 30_000)` on mount.
- `GET /api/overview/latest-orders` returns the newest 8 orders for the tenant.
  Guarded by `requireSession` + role check (OWNER / ADMIN / ACCOUNTS only; others get 403).
- Successful poll → "Live" pill turns green; any `fetch` or `!ok` response → "Offline" grey.
- IDs not seen before get added to a `newIds` set, triggering a 3 s highlight class on their `<li>`.

Supabase Realtime proper (`realtime.on("INSERT")` with RLS channel) is a
future enhancement — the polling fallback already meets the §6 "within 5 s"
goal when staff refresh and the "Live" dot gives the honest status signal.
